# Overcharge

Open the orange Overcharge button beneath the Index. The panel previews permanent bonuses, three requirements and reset/retention rules. Qualified players press Overcharge, then Confirm Reset. Close/Escape cancels the confirmation. Requests validate the current Overcharge count, all requirements and a living character on the server, with a one-second rate limit; replaying an old count cannot award another reset.

Tune `src/shared/OverchargeDefinitions.luau`. First requirements: Level 25, 10,000 Power and $10,000 cash. Later requirements add five Levels and multiply the Power/cash targets by 1.6 per completed Overcharge. Bonuses add 0.5 to the Power multiplier and 0.2 to the cash multiplier each time: first 1.5x/1.2x; second 2x/1.4x; third 2.5x/1.6x. These are provisional economy values for playtesting.

Power multiplies training Power and XP gains, including immediate local prediction and floating feedback. Fractional values are preserved: the starter gives 1.5 Power/XP after the first reset. Damage still equals accumulated Power; it is not multiplied again. Cash multiplies ore sale totals, held-core prices and bulk-core prices, then rounds the final payout down to whole dollars. Quotes include the bonus. Future reactor income should use `PlayerDataService.GetCashPayout` when collected; reactor earnings are not implemented yet.

Reset fields: Power, XP, Level, cash, materials, weapon ownership/equipped weapon, all normal upgrades, backpack capacity and Unknown Core capacity. Stored Unknown Cores, stabilized cores, running stabilizations, reactor data, Index discoveries, first-core history and lifetime blocks mined stay intact. Mine damage, uncollected drops and sale offers clear; the player returns to the lobby with Scrap Zapper. Stored cores are synced back into the hotbar. Count is already part of the saved profile; multipliers derive from it on load. A new progress epoch clears predicted training clicks from the previous run and rejects stale training messages.

Editable UI: paste `studio/build_overcharge_gui.lua` in the Edit Command Bar after Rojo sync. It preserves existing edits. Edit `StarterGui.OverchargeGui.OverchargeButton`, `Shade.Panel` and `CelebrationLabel`. Named reward/requirement/reset labels and confirmation controls use scale sizing and TextScaled. Controller updates live stat text; edit labels/layout in Studio and tune economy in the definitions module.
